# 결과보고서 양식 보존 재편집 설계

## 목표

- 원본 `2026 오픈소스 개발자대회 결과보고서_433(FiTuna).docx`는 변경하지 않는다.
- 공식 결과보고서 본문 표의 행·열·셀 병합, 용지 방향, 여백, 글꼴 체계, 제목과 문체를 그대로 유지한다.
- 붙임을 제외한 본문 6쪽을 5쪽 이내로 줄인다.
- 처음 보는 심사위원이 필요성, 구현 내용, 실측 경쟁력, 오픈소스 완성도를 빠르게 파악하도록 셀 내부 문장을 다듬는다.

## 검토한 접근

1. **보수적 인라인 압축(채택)**: 기존 표와 실측 비교표를 유지하고, 중복·장문·설명 순서만 셀 안에서 정리한다. 양식 위반 위험이 가장 낮다.
2. 셀 내부에 도식·그래프 추가: 작은 셀에서 글자가 작아지고 본문 분량이 늘어나므로 제외한다.
3. 표 재구성·페이지별 레이아웃 변경: 공식 예시와 달라지므로 제외한다.

## 본문 편집 범위

- `프로젝트 소개`: 기능·입력·출력을 한 문장으로 명확히 정리한다.
- `개발배경 및 목적`: 중복된 Gartner 문장과 장황한 기존 도구 설명을 줄이고, 문제·기존 한계·FiTuna의 해결 방식 순서로 정리한다.
- `개발환경`: 기술 스택과 검증 근거는 유지하되 한 항목 한 줄로 압축한다.
- `시스템 구성 및 아키텍처`: 계층 설명은 쉬운 한국어를 먼저 쓰고 파일명은 근거로만 병기한다. 새 도식은 넣지 않는다.
- `프로젝트 주요기능`: 기능 설명, 개발 과정, 협업·관리, 구동·시연, 실측 비교표를 모두 유지하되 반복되는 효과 설명을 제거한다.
- `기대효과 및 활용분야`: 탐색·캐시 효과와 사용자군은 유지하고 외부 시장 통계와 중복된 카테고리 설명은 대폭 줄인다.
- `기타`: 혁신성·한계·로드맵·소감을 유지하되 구현되지 않은 장기 계획의 세부 나열을 줄인다.

## 붙임

- `붙임1 SBOM`: 기존 가로 양식과 열 구성을 유지한다. 최대 10개라는 안내에 맞춰 실제 사용 관계가 분명한 오픈소스 구성요소만 남기고 독점 도구는 제외한다.
- `붙임2 AI 모델 활용 및 라이선스 기술 명세서`: FiTuna는 AI 모델을 탑재·학습·배포하지 않고 외부 모델을 벤치마크 대상으로만 사용하므로 공식 안내에 따라 삭제한다.

## 검증 기준

- 원본 SHA-256이 편집 전후 동일해야 한다.
- 수정본 본문은 5쪽 이내이며 붙임은 별도 분량으로 계산한다.
- 본문 표의 행·열·셀 병합 구조와 두 섹션의 페이지 설정이 원본과 동일해야 한다.
- 수정본을 새 LibreOffice 프로필로 PDF 변환하고 모든 페이지를 이미지로 확인한다.
- 잘림, 겹침, 빈 페이지, 지나치게 작은 글자, 붙임 시작 위치 오류가 없어야 한다.
